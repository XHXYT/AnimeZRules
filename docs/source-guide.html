AnimeZ 写源指南

一个"源"就是一个 JSON 文件，它告诉 AnimeZ：

  • 去哪个地址请求（搜索页 / 接口）
  • 从返回内容里怎么取出视频列表和字段
  • 详情页、选集、真实播放地址怎么解析

写源有两条路：在电脑上写 JSON 文件再导入应用，或者直接在应用内的源编辑页填写（视频源页 → 添加新数据源 / 点击已有源）。两者完全等价，本档前半部分讲清每个配置字段的含义，应用内编辑器对照一节则把编辑页每个输入框逐一对应到这些字段——纯手机操作时建议开着本页对照填写。

AnimeZ 引擎支持两种解析模式，由 parserConfig.sourceType 决定：

模式适用站点定位方式典型例子
"html"（默认） 传统服务端渲染网页（苹果 CMS 模板站等） CSS 选择器（如 a.module-item@href） 各类苹果 CMS 模板站
"json" 前后端分离站点（REST API） JSON 路径 + {字段} 模板 各类提供公开接口的站点

两种模式可以混用同一套配置结构：JSON 模式下，原本填 CSS 选择器的字段改填 JSON 路径或模板；个别字段是 JSON 模式专属（如 listPath、jsonRoutesPath），文档中会单独标注。

文件结构

一个规则文件 = 一个 sources 数组 + 元信息：

{
  "version": "1.0.0",            // 配置版本号
  "author": "yourname",          // 作者
  "update_time": "2026-09-23",   // 更新日期
  "sources": [
    {
      // 这里是一个数据源（DataSourceConfig），见下一节
    }
  ]
}
应用"导入数据源"还兼容单个源对象和源对象数组两种格式，但提交到本仓库时请统一使用上面的完整格式。
导入时，文件级的 author / update_time 会自动下沉到每个未自带这两个字段的源上（源级字段优先）。也就是说文件里写了 "author": "user"，导入后每个源的"作者"都会是 user，可在应用内编辑页单独修改。

源基础字段

每个 sources[] 元素的结构：

字段类型必填说明

namestring必填显示名称，如 "示例动漫"
groupstring必填分组，如 "动漫"
baseUrlstring必填站点根地址，如 https://www.example.com/。所有相对 URL、{baseUrl} 模板都基于它

authorstring可选源作者。导入配置文件时若源未自带，会继承文件级 author；应用内编辑页"基本"Tab 可填写，导出时随源携带
update_timestring可选源级更新日期（YYYY-MM-DD）。导入时同样继承文件级值；应用内编辑保存时自动更新为当天
enabledboolean可选是否启用，默认 true
prioritynumber可选优先级，数值越小越靠前
descriptionstring可选源介绍（可注明播放限制，如 "播放需账号登录"）

parserConfigobject必填解析配置，本文档的主角

登录配置 login

部分站点的播放接口需要登录凭证。配置后，源列表长按源卡片会出现"账号登录"入口；登录成功取得的凭证会自动附加到该源的所有 API 请求上。两种登录类型：

  • api（默认）：JSON API token 登录——POST 登录接口，从响应 JSON 按 tokenPath 取 token，附加到 authHeaderName 请求头（如 Authorization: Bearer xxx）；
  • cookie：Cookie 会话登录——POST 登录接口后捕获响应 Set-Cookie（拼接 name=value; ...，并解析 Expires 作为过期时间），后续请求经 authHeaderName: "Cookie" 回放。适合 Connect-RPC 等只认会话 Cookie、不认自定义 token 头的站点（参考 milimili 源）。
"login": {
  "type": "api",                       // "api"（默认，可省略）| "cookie"
  "loginUrl": "/api/auth/login",       // 登录接口（相对 baseUrl 或绝对）
  "usernameField": "username",         // 请求体用户名字段名，默认 username
  "passwordField": "password",         // 请求体密码字段名，默认 password
  "extraBody": { },                    // 额外固定请求体字段（可选，支持布尔值如 {"remember":true}）
  "tokenPath": "data.token",           // api 模式：token 在登录响应中的 JSON 路径，默认 data.token
  "authHeaderName": "Authorization",   // 携带凭证的请求头名，默认 Authorization（cookie 模式配 "Cookie"）
  "authValueTemplate": "{token}"       // 请求头值模板，默认 {token}
}

cookie 模式示例（虚构 Connect-RPC 站，登录接口与业务接口同为 POST 端点）：

"login": {
  "type": "cookie",
  "loginUrl": "/platform.v1.AccountService/Login",
  "usernameField": "handle",
  "passwordField": "password",
  "extraBody": { "remember": true },
  "authHeaderName": "Cookie",
  "authValueTemplate": "{token}"
}
authValueTemplate 支持前缀写法，例如站点要求 Bearer xxx 时填 "Bearer {token}"。登录响应/业务响应的错误消息兼容 msg 与 message 两种字段名（Connect-RPC 用 message，如 401 {"code":"unauthenticated","message":"请先登录"} 会直接提示"请先登录"）。

parserConfig 总览

"parserConfig": {
  "sourceType": "html",               // "html" | "json"，缺省 html
  "requestHeaders": { },              // 该源所有请求附加的自定义请求头（JSON 源常用）
  "search":   { "videos": VideoConfig },
  "homepage": { "banner": VideoConfig, "category": CategoryConfig },
  "detail":   DetailConfig,
  "videoUrl": VideoUrlConfig,
  "schedule": ScheduleConfig          // 可选：周表（配置后成为设置"周表数据源"候选）
}

其中 search、homepage、detail、videoUrl 分别对应应用内的四个功能环节：搜索 → 首页浏览 → 详情页 → 播放；schedule 为可选的周表能力（主页旁的"周表"Tab）。

选择器语法（HTML 模式）

HTML 模式的核心语法：CSS 选择器 + @ 属性。

写法含义示例
选择器取元素的文本内容（自动 trim、反转义 HTML 实体）.module-card-item-title
选择器@属性取元素的指定属性值a@href、img@data-original
@属性选择器为空时取条目元素自身的属性（条目本身即 <a> 时常用）@href
懒加载图片通常不在 src 而在 data-original / data-src 等自定义属性里，F12 看清楚再填。

此外每个字段都可以用复杂形式附加后处理（详见字段后处理）：

"title": {
  "selector": ".module-card-item-title",
  "postProcess": { "type": "string", "stringProcess": { "type": "replace", "search": "免费", "replace": "" } }
}

VideoConfig：列表解析的通用结构

搜索结果、横幅、分类视频、推荐列表都是同一种结构：

字段模式说明
urlTemplate两者请求地址模板。HTML：相对/绝对页面地址，支持 {keyword}（自动 URL 编码）、{page} 占位符；JSON 模式下搜索必填，首页横幅等直接请求 url 的场景可不填
listSelectorHTML列表条目的 CSS 选择器，如 div.module-card-item，命中几个元素就有几条结果
listSelectorJSON列表在响应中的 JSON 路径，如 data.list；以 regex: 开头时改为"正则捕获 JSON 数组"（用于 RSC/flight 等夹在 HTML 里的数据）
containerSelectorHTML可选。先定位列表容器，再在容器内用 listSelector 找条目（"更多"分页页等整页文档用）
urlNeedBaseUrl两者结果 URL 是相对路径时填 true，引擎自动拼接 baseUrl
enabledHttps两者true 时把取到的 http:// 地址升级为 https://
itemSelectors两者字段选择器（HTML）或字段模板（JSON），见下

itemSelectors 支持的四个字段：

字段HTML 填法JSON 填法
urla@href（详情页地址，必填）"{baseUrl}/api/videos/{video_id}"
imgUrlimg@data-original"{cover_url}"
title.module-card-item-title"{title}"
episode.module-item-note（集数/备注角标）"{remarks}"

路径与模板（JSON 模式）

JSON 路径

用点分隔逐层取值，数组元素用数字下标：

data.list          → resp.data.list
data.list.0.videos → resp.data.list[0].videos（横幅等嵌套场景）
play_from          → 顶层数组字段

字段模板 { }

  • {baseUrl}：固定替换为源根地址；
  • 其余 {xxx}：按点分路径从当前上下文对象取值，如 {video_id}、{actor.name}；
  • 取到数组时以 / 连接（如多分类标签 {categories}）；
  • 取不到值时替换为空字符串。

模板可以任意混排文字："{baseUrl}/api/video/{id}/episodes?route={route}&page=1"。

不同位置能引用的上下文不同：搜索/列表 = 条目自身字段；选集 = 详情字段 + 路线字段 + 剧集字段 + {routeIndex}（路线序号，从 0 开始）。详见选集一节。

JSON 模式的请求行为

  • 相对地址自动拼 baseUrl；
  • 自动附加 parserConfig.requestHeaders 与登录 token；
  • 响应是对象且 code 存在且非 0 也非 200 时，视为业务错误：抛出 msg（缺省时依次取 message、"接口返回错误码 N"）作为错误信息（兼容 0 与 200 两种成功码约定，如 sorani 用 code:200 表示成功；Connect-RPC 风格错误用 message 字段）。

POST 请求（method/body，可选）

JSON 模式的每个请求端点都可声明 method 与 body（缺省 GET，不声明即完全沿用原行为），用于 Connect-RPC 等 POST 型 JSON 接口：

"search": {
  "videos": {
    "urlTemplate": "/api.example.com/bangumi.v1.BangumiService/SearchBangumi",  // POST 时即接口端点，可为绝对地址
    "method": "POST",
    "body": '{"keywords":"{keyword}","page":{page}}',   // JSON 请求体模板
    "listSelector": "data.list",
    "itemSelectors": { "title": "{title}", "url": "{baseUrl}/video/{seasonId}", "imgUrl": "{coverUrl}" }
  }
}
字段说明
method请求方法，缺省 GET；设为 POST 时以 application/json 发送 body 渲染后的请求体
bodyJSON 请求体模板。占位符取值后做 JSON 字符串转义（引号/反斜杠安全，非 URL 编码），保证请求体合法；支持值变换占位符 {路径#正则#替换}——取值后先做一次正则替换再转义嵌入（如 {link#^.*[?&]ep=(\d+).*$#$1} 从选集链接中提取剧集编号），正则失败回退原值

各端点 body 可用的占位符：

端点配置位置占位符
搜索search.videos{keyword}、{page}
首页"更多"列表homepage.category.videos{page}
首页分类卡片 / 轮播category.cards[] / banner无（写固定请求体）
周表schedule{weekday}（1-7）、{weekday0}（0-6）
详情接口detail{link}（搜索结果里存的详情地址/ID）
选集接口detail.episodes详情字段点分路径（与 jsonSectionsUrlTemplate 同上下文，含路线字段）
推荐接口detail.recommends详情字段点分路径（与 jsonUrlTemplate 同上下文）
播放地址接口videoUrl（pattern=json）{link}（剧集 link）；配置 urlTemplate 时剧集链接仅作占位符上下文，见播放地址一节
Connect-RPC 站点通常还需要附加请求头（如 Connect-Protocol-Version: 1），用源级 requestHeaders 配置即可，无需引擎额外支持。POST 端点的 urlTemplate 可为绝对地址（独立接口域名），引擎不再强拼 baseUrl。

可选扩展字段

itemSelectors 支持以下可选字段键，提取结果会挂在 VideoInfo 上（均为可选，源里有什么配什么，未配置即为空）：

字段键含义示例值
playCount播放量1854 / 1.2万
year播出年份2012
month播出月份04 / 四月
director导演武本康弘,木上益治
actors声优中村悠一,佐藤聪美
tags标签/类型悬疑,校园,日常
每个字段都可以用「简单选择器字符串」或「{ selector, postProcess } 复杂配置」两种形态；配合 nth-child(n)/nth-of-type(n) 伪类可取同容器第 n 个元素，配合 :contains(文本) 伪类可按文本内容筛选元素（如 .slide-info.partition:contains(导演) 取行首带「导演」的行——条目行数不固定时比按序号取更稳），配合 postProcess（regex/replace 等表单类型）可清洗文本（如去掉「导演 :」前缀）。多值字段建议保留原始分隔符（如英文逗号），由 UI 自行切分展示。应用内编辑器中这组字段收在「更多字段」开关下，配置任一字段即展开；后处理请优先使用表单类型（字符串替换/正则提取等），pipeline 等高级形态仍可通过「JSON(高级)」编辑。

搜索验证码 captcha（可选）

部分站点（MacCMS dsn2 模板常见）搜索会返回验证码页。配置后引擎自动走「获取验证码图片 → 搜索页弹窗输入 → 提交校验 → 同会话重放搜索」流程，全程共享 Cookie 会话：

"search": {
  "videos": { "..." : "同上" },
  "captcha": {
    "detectSelector": "img.ds-verify-img",        // 命中该选择器说明响应是验证码页
    "imageUrlSelector": "img.ds-verify-img@src",  // 验证码图片选择器（selector@attr）；留空且判定元素本身是 img 时自动回退为 detectSelector+@src
    "imageNeedBaseUrl": true,                     // 图片地址是否拼 baseUrl，默认 true
    "imageCacheBustParam": "r",                   // 获取图片时附加 ?r=随机数 防缓存（可选）
    "imageUrlTemplate": "/index.php/verify/index.html?",  // 可选：图片固定地址模板（相对 baseUrl 或绝对地址）
    "verifyUrlTemplate": "/index.php/ajax/verify_check?type=search&verify={code}",  // {code}=用户输入
    "successContains": "\"code\":1"               // 提交响应包含该子串视为成功（可选）
  }
}
验证码弹窗只在搜索页出现；未配置或校验连续失败 3 次时按普通搜索失败处理。前提是站点验证流程为「图片 + 提交校验 + 会话 Cookie 生效」，带滑动/点选等交互验证的站不适用。

imageUrlTemplate 是图片地址的兜底模板：部分站点验证码图片由页面 JS 动态注入，搜索响应里根本没有 img 元素（或选择器取不到地址）时，改用该固定地址获取图片（如 MacCMS 的 /index.php/verify/index.html，配合 imageCacheBustParam 防缓存）。imageUrlSelector 能正常取到图片时不会用到它。

HTML 模式——urlTemplate 决定轮播数据来源页：留空（或与首页相同）时直接解析首页文档；填其他地址（相对路径拼 baseUrl，也可绝对地址）时引擎会独立请求该页解析轮播。站内没有真轮播时，可把分类列表页（如"剧场版"）当地播页使用；首页本身已有可用区块时，也可留空并用组合器 + :contains 定位（如 div.title:contains(剧场版) + div div.public-list-box，见 mgnacg 源）。

分类 category

HTML 模式——从首页 DOM 中同时解析多个分类板块：

"category": {
  "title": "h2.module-title",                    // 单个板块标题的选择器
  "titles": "div.module > div.module-heading",   // 所有板块标题的选择器（与 videoLists 数量对应）
  "moreUrl": "a.module-heading-more@href",       // 板块"更多"链接
  "moreUrlNeedBaseUrl": true,
  "videoLists": "div.module > div.module-main",  // 所有板块列表容器的选择器
  "videos": {                                    // 每个板块内的条目解析（VideoConfig）

  ]
}
HTML 模式的"更多"分页页同样用 videos（含 containerSelector）解析整页文档；卡片 moreUrl 支持 {page} 占位符（如 /show/2--------{page}---/），未使用占位符时沿用旧行为（页码直接拼在地址末尾）。卡片请求失败或解析为空时引擎自动重试一次（间隔 300ms），避免站点偶发限流导致卡片空白。

周表 schedule

可选节点。配置后该源成为设置页 "周表数据源" 的候选；用户在 设置 → 周表数据源 中选定后，应用主页旁的"周表"Tab 按星期（周一~周日）展示该源的番剧更新列表。未选择周表源（或所选源被删除/停用）时周表页显示空态引导。结构与列表卡片同构，唯一的新概念是地址模板中的 {weekday} 占位符（1=周一 … 7=周日，切换星期时替换后重新请求）：

"schedule": {
  "urlTemplate": "/api/index/weekday?weekday={weekday}",   // {weekday} 为星期占位符，相对路径拼 baseUrl
  "listSelector": "data.list.0.videos",                    // HTML=条目 CSS 选择器 / JSON=列表 JSON 路径
  "urlNeedBaseUrl": false,
  "enabledHttps": true,
  "itemSelectors": { "title": "{title}", "url": "{baseUrl}/api/videos/{video_id}", "imgUrl": "{cover_url}", "episode": "{remarks}" }
}
字段说明
urlTemplate周表数据地址模板；{weekday} 会被替换为 1-7（周一=1），{weekday0} 替换为 0-6（周一=0，适配 0 起始的星期字段/接口，如某接口的 update_weekday）。相对路径自动拼 baseUrl，也可填绝对地址
listSelectorHTML 模式=条目 CSS 选择器；JSON 模式=当天列表在响应中的 JSON 路径（如 data.list.0.videos），可留空（空=响应根数组）
weekdayBlocksSelector 可选 仅HTML首页多区块形态：一周各天分区在同一页面时，填所有星期区块的容器选择器（如 .anime-schedule）。引擎按区块标题文本（"星期三/周三/水曜日/Wednesday"）定位对应星期的区块，再在其中用 listSelector 提取条目；区块顺序无关（"今天在前"轮转也能正确匹配），找不到对应区块视为当天无更新
weekdayTitleSelector 可选 仅HTML每个区块内标识星期的标题元素选择器（如 h4），与 weekdayBlocksSelector 配套使用
itemSelectors字段选择器/模板，与搜索结果、分类卡片完全相同（url/imgUrl/title/episode + 扩展字段）
urlNeedBaseUrl / enabledHttps同 VideoConfig：条目 url 相对路径拼接、http 升级 https

首页多区块形态示例（某站：首页 7 个"星期X"区块即周表数据）：

"schedule": {
  "urlTemplate": "/",                          // 首页本身
  "weekdayBlocksSelector": ".anime-schedule",  // 所有星期区块
  "weekdayTitleSelector": "h4",                // 区块标题（星期一~星期日）
  "listSelector": ".anime-card",               // 区块内条目
  "urlNeedBaseUrl": true,
  "enabledHttps": true,
  "itemSelectors": { "url": "a.stretched-link@href", "imgUrl": "img.anime-cover@data-src", "title": "a.stretched-link", "episode": ".anime-update-info p" }
}
周表按天懒加载并缓存：切到某天才请求当天接口，再次切换直接用缓存。周表源独立于首页数据源，在 设置 → 周表数据源 中选择；站点若提供"不带星期参数返回全周"的接口，也请逐天配置（按天请求语义更明确）。JSON 源的 urlTemplate 可直接带站点过滤参数——如 PostgREST 风格参数 is_finished=eq.false 只取连载中的新番，否则会把历史上所有星期几更新的老番都列出来。

详情 detail

进入详情页后，引擎请求 url（列表阶段取到的地址）并解析以下字段。

HTML 模式——全部是选择器：

"detail": {
  "titleSelector": ".module-info-heading h1",
  "descSelector": ".module-info-introduction-content p",
  "coverSelector": ".module-info-poster img@data-original",
  "categorySelector": ".module-info-tag a",        // 可选：分类
  "updateTimeSelector": ".module-info-item-content", // 可选：更新时间
  "extra": { ... },          // 可选：扩展字段（导演/声优/标签/年月/播放量，见下）
  "episodes": { ... },      // 见下一节
  "recommends": { ... }     // 见推荐一节
}
titleSelector / descSelector 支持三种形态：①纯文本选择器（取元素文本）；②选择器@属性（取属性值，如 meta[name=description]@content，适合详情页无结构化简介、只有 meta 标签的站）；③对象形态 { "selector": "...", "postProcess": { ... } }（选择器同样支持 @属性，先取值再做后处理，如标题去掉「热度：xxx」后缀——参考 7sefun 源）。

JSON 模式——link 是接口地址（或业务 ID，见 urlTemplate），字段全部改填 { } 模板（上下文 = 详情接口响应对象）：

"detail": {
  "urlTemplate": "/api.example.com/bangumi.v1.BangumiService/GetBangumi",  // 可选：详情端点地址模板
  "dataPath": "0",               // 可选：详情数据在响应中的 JSON 路径，默认 data（支持数组索引）
  "titleSelector": "{title}",
  "descSelector": "{description}",
  "coverSelector": "{cover_url}",
  "categorySelector": "{categories}",
  "updateTimeSelector": "{publish_date}",
  "coverPostProcess": { ... },   // 可选：封面地址后处理（ProcessConfig），如改写为图片代理地址
  "extra": { ... },              // 可选：扩展字段（导演/声优/标签/年月/播放量，见下）
  "episodes": { ... },
  "recommends": { ... }
}

默认从响应的 data 字段取详情对象；接口直接返回数组或对象本身时用 dataPath 指定（支持点分路径与数组索引，如 PostgREST 数组响应填 0；显式填空串 "" 表示响应根对象本身，应用内编辑器中输入 . 即映射为空串——详情字段与剧集数组平级、没有统一包裹字段时用它，参考 milimili 源）。

urlTemplate（可选）配置后，引擎不再直接请求列表阶段存下的 link，而是以 {link} 占位符渲染该模板得到详情端点地址（相对路径拼 baseUrl）。适用于搜索结果只能存业务 ID（如 shortId）、需要拼出固定端点才能查详情的接口站（如 Connect-RPC 的 GetBangumi）。配合 method/body（见POST 请求）可在请求体里带上 "id":"{link}"。未配置时沿用旧行为：link 本身即详情接口地址。

详情扩展字段 extra（可选）

extra 的键与「可选扩展字段」一节完全相同（playCount / year / month / director / actors / tags，其中 actors 为声优），用于补充/丰富详情信息；详情的导演、声优等信息统一配在这里。HTML 模式值为 CSS 选择器，JSON 模式值为 { } 模板，同样支持 { selector, postProcess } 复杂配置。旧版基础字段 directorSelector / protagonistSelector 仅为兼容保留（extra 优先，二者等价），应用内编辑器已不再提供这两个入口，旧源在编辑器中打开时会自动迁移到 extra；新建源请直接使用 extra：

"extra": {
  "director": { "selector": ".slide-info.hide.partition:contains(导演)",
                "postProcess": { "type": "string", "stringProcess": { "type": "replace", "search": "^(导演|演员|类型)\\s*:\\s*|\\s*[,，]\\s*$", "replace": "", "flags": "g" } } },
  "actors": { "selector": ".slide-info.hide.partition:contains(演员)", "postProcess": { "...": "同上" } },
  "tags":   { "selector": ".slide-info.hide.partition:contains(类型)", "postProcess": { "...": "同上" } },
  "year":   { "selector": ".slide-info-remarks:nth-of-type(2)",
              "postProcess": { "type": "string", "stringProcess": { "type": "regex", "pattern": "\\d{4}" } } },
  "month":  { "selector": ".slide-info-remarks:nth-of-type(3)",
              "postProcess": { "type": "string", "stringProcess": { "type": "regex", "pattern": "[一二三四五六七八九十]{1,3}月" } } }
}
导演/声优/类型行用 :contains(标签文字) 按行首标签选行（匹配的是源站行首文字，与应用内字段名无关），条目缺行（如电影条目没有声优行）时对应字段为空、不会错位到别的行；年月等固定次序的行仍可用 nth-of-type(n)。应用内编辑器中该组字段收在详情页签的「更多字段」开关下（播放量/年份/月份/导演/声优/标签），配置任一字段即展开，全部清空后开关关闭并移除 extra 节点。提取结果挂在 VideoDetailInfo 上，与列表阶段的同名扩展字段结构一致；详情页的「声优」节优先显示 actors，旧数据 protagonist 作兜底。

选集 episodes

HTML 模式：单路线 / 多路线

"episodes": {
  // —— 多路线（多播放源）——
  "routeTitlesSelector": "#y-playList .module-tab-item > span",      // 路线标题（如"播放1""备用2"）
  "routeContainersSelector": "#panel1 .module-play-list-content",    // 每条路线的列表容器
  // —— 多路线·按路线选择器（线路按钮与剧集组无父子关系时，替代 routeContainersSelector）——
  "routeItemSelectors": [".circuit_switch1 a", ".circuit_switch3 a"], // 每条路线的剧集选择器，与标题按序配对
  "routeTitleProcess": {                                            // 可选：路线标题后处理（如去除角标数字）
    "type": "string", "stringProcess": { "type": "replace", "search": "\\s*\\d+$", "replace": "", "flags": "g" }
  },
  "routeExcludeKeywords": ["已下线", "APP专线"],                     // 可选：路线标题命中任一关键词即整条跳过
  // —— 单路线 ——
  "containerSelector": ".module-play-list-content",                  // 列表容器（与上面二选一）
  // —— 公共 ——
  "itemSelector": ".module-play-list-link",                          // 单集条目
  "itemSelectors": {
    "url": "@href",                                                  // 播放页地址
    "title": "span"                                                  // 集名，如"第01集"
  }
}
单路线用 containerSelector + itemSelector；多路线用 routeTitlesSelector + routeContainersSelector + itemSelector，标题与容器按顺序配对；页签式页面（线路按钮与剧集组无父子关系）改用 routeTitlesSelector + routeItemSelectors[]，每条路线写一个选择器、与标题按序配对，必要时配 routeTitleProcess 清洗标题、routeExcludeKeywords 过滤无效路线。routeExcludeKeywords 同样适用于 JSON 模式（按 jsonRouteTitleTemplate 渲染出的标题过滤）。

JSON 模式：路线 + 选集接口

"episodes": {
  "jsonRoutesPath": "play_from",                 // 详情响应中的路线数组路径，每项描述一条播放路线
  "jsonRouteTitleTemplate": "{title}",           // 路线标题模板（上下文 = 详情字段 + 路线项字段，路线优先）
  "jsonSectionsUrlTemplate": "{baseUrl}/api/video/{id}/episodes?route={route}&page=1&page_size=100",
                                                // 每条路线独立请求选集接口；不填则视为剧集内嵌在路线对象中
  "jsonListPath": "data.list",                   // 剧集列表在选集响应中的 JSON 路径，默认 data.list
  "itemSelector": "",
  "itemSelectors": {
    "title": "{title}",
    "url": "{baseUrl}/api/v2/sections/{id}/play-url"   // 该集的"播放地址"（通常是解析接口，交给 videoUrl 换取直链）
  }
}

剧集字段模板的上下文 = 详情字段 + 路线字段 + 剧集字段（后者覆盖前者），另有 {routeIndex} 可用（路线序号，从 0 开始）——当不同路线的解析接口不同时可以用它做判断类后处理。

不配置 jsonRoutesPath 时进入单路线模式：详情数据自身作为唯一路线，jsonListPath 相对详情对象取剧集数组，路线标题模板上下文 = 详情字段。适用于剧集列表直接内嵌在详情响应里的接口（如 PostgREST 关联嵌入 select=*,episodes(...)），只需一次请求同时拿详情和选集。

推荐 recommends

结构即 VideoConfig：

// HTML 模式
"recommends": {
  "urlTemplate": "/hot/list.html",               // 可选：推荐独立页地址（相对拼 baseUrl 或绝对）；
                                                // 不填=解析详情页本身；详情页无推荐区块、但站内有
                                                // 热门列表/热门搜索页时可填它充当（listSelector 相对该页）
  "listSelector": "div.module-poster-items-base a.module-poster-item",
  "urlNeedBaseUrl": true,
  "enabledHttps": true,
  "itemSelectors": { "url": "@href", "imgUrl": "img@data-original", "title": ".module-poster-item-title", "episode": ".module-item-note" }
}
// JSON 模式：listSelector 填 JSON 路径，另加 jsonUrlTemplate 指定推荐接口（上下文 = 详情字段）
"recommends": {
  "listSelector": "data.list",
  "itemSelectors": { "title": "{title}", "url": "{baseUrl}/api/videos/{video_id}", "imgUrl": "{cover_url}", "episode": "{remarks}" },
  "urlNeedBaseUrl": false,
  "enabledHttps": true,
  "jsonUrlTemplate": "{baseUrl}/api/videos/{id}/recommendations?limit=6"
}
JSON 模式必须配置 jsonUrlTemplate（不填则推荐恒为空，引擎不会从详情响应里找推荐）；HTML 模式默认仅用 listSelector（无 containerSelector）在详情页文档内选取，配置 urlTemplate 后改为独立请求该页解析（请求失败仅放弃推荐，不影响详情）。两种模板均支持 {rand:最小,最大,步长} 随机占位符（在区间内按步长随机取一个值，如 {rand:0,200,10} → 0/10/20/…/200），用于推荐页随机翻页，让每次进详情看到不同推荐。

实战定位技巧：

  • 区块定位组合器：推荐卡片本身往往没有专属容器，可用标题文本 + 相邻组合器锁定区块，如 div.title:contains(相关影片) + div div.card（"标题为『相关影片』的 div 的下一个兄弟 div 内任意层级的 .card"）。注意详情页推荐卡片的类名经常与搜索结果卡片不同，不要照搬 search 的 itemSelectors，逐字段在详情页 HTML 里核实。
  • 多 tab 推荐区：有的站按题材分多个 tab 展示相关内容，多个 ul 中通常仅当前 tab 带 current/active 类——用 .tabs ul.current li 之类限定到首个 tab 即可，不必抓全部。
  • POST 型推荐接口：JSON 模式支持 method + body（与搜索/详情同构，Connect-RPC 类接口可用），body 模板占位符取详情字段并做 JSON 转义，如 {"videoId":"{video.id}","limit":6}。
  • 独立推荐页：详情页没有推荐区块、但站内有现成的热门列表页或热门搜索页时，HTML 模式可配 urlTemplate 指向该页，让引擎单独请求并解析（listSelector/itemSelectors 相对该页 DOM）。若该页与本站搜索结果页同构（如同一搜索端点换参数），字段选择器可直接照搬 search；地址中的固定中文关键词可直接写 URL 编码后的形式（如 searchText=%E8%A1%A5%E7%95%AA），配合 {rand:0,200,10} 占位符还能在该热门页内随机翻页。
  • 由详情地址构造推荐页：HTML 模式 urlTemplate 的上下文含 {link}（当前详情页地址），并支持值变换占位符 {link#正则#替换}（对详情地址做正则替换后拼入，# 分隔，正则失败回退原串）。站点推荐只出现在播放页（如 /play/123-1-1.html）而详情页是 /show/123.html 时，可写 {link#^https?://[^/]+/show/(\d+)\.html$#/play/$1-0-0.html} 把详情地址改写成播放页地址（参考 baimao）。
  • 无独立推荐端点的 JSON 站：详情响应只有 ID 数组、或根本没有相关字段时，可用「同分类列表」接口充当推荐——把详情的分类字段注入列表接口的过滤参数，如 {baseUrl}/api/videos?page=1&size=12&categoryId={video.categoryId}（字段名按站点实际支持的过滤参数核实，注意有的站不认识的参数会被静默忽略，务必对比有无参数的 total 是否变化）；列表响应结构则照搬 search 的 listSelector/itemSelectors。此法无法排除当前作品自身，可接受再使用。连可用的过滤参数都没有、详情页也无推荐区块时，留空跳过（推荐是可选能力）。

播放地址 videoUrl

选集拿到的 url 往往只是播放页/解析接口，videoUrl 负责把它换成真正可播放的直链。按 pattern 分四种：

pattern行为关键字段
"regex" 请求 url 拿到原始文本，用正则提取（取捕获组 1） urlSelector = 正则表达式（此模式下含义是正则）
选择器模式
（不填 pattern）		 请求 url 拿到 HTML，用选择器提取属性 urlSelector = 选择器@属性
"json" 请求播放地址接口（JSON），按路径取值 valuePath = 播放地址 JSON 路径，默认 data.url；可选 urlTemplate 指定接口地址（见下）
"link" url 本身就是播放页地址，直接透传（通常配合 iframeSelector 交给 WebView 解析） —

regex 模式示例（模板站常见：从播放页内嵌 JSON 中抠出直链）：

"videoUrl": {
  "pattern": "regex",
  "urlSelector": "\"url\":\"([^\"]+)\",\"url_next\"",
  "postProcess": "replaceAll('\\\\/', '/')"     // 旧版字符串后处理，处理 \/ 转义
}

json 模式示例（接口站）：

"videoUrl": { "pattern": "json", "valuePath": "data.url" }

json 模式进阶——urlTemplate（可选）：播放接口地址与选集链接不是同一个时配置（如 Connect-RPC 站选集链接是 watch 页、播放接口是独立取流端点）。配置后引擎改为请求渲染后的模板地址（相对拼 baseUrl 或绝对），选集链接仅作 {link} 占位符上下文；配合 body 值变换占位符从链接中提取参数，配合 login（cookie 模式）携带登录态（参考 milimili 源）：

"videoUrl": {
  "pattern": "json",
  "urlTemplate": "/platform.v1.BangumiService/GetPlayUrl",
  "method": "POST",
  "body": '{"ep":"{link#^.*[?&]ep=(\\d+).*$#$1}","client":"web"}',
  "valuePath": "data.playUrl"
}
选集链接形如 https://<站点>/watch?ep=<编号>，值变换占位符从中提取 ep 编号注入请求体；未登录时接口返回 401，错误消息"请先登录"会直接提示到播放页，引导用户去源列表长按登录。

三种请求型 pattern 均支持旧版字符串 postProcess，共五种（按固定顺序生效）："substringBetween('start','end')"、"replaceAll('old','new')"、"base64Decode()"（Base64 解码，UTF-8）、"decodeUri()"（URL 解码）、"jsonDecode()"（JSON 字符串解码，正确处理 \/ 与 \uXXXX 中文转义——播放地址里含中文路径时用它，别用 replaceAll 删反斜杠）。典型组合——MacCMS 播放地址 player_aaaa 的 encrypt=2 加密："base64Decode();decodeUri()"；player_aaaa.url 带转义："jsonDecode()"。

iframeSelector（可选）：真实地址需要执行页面 JS 才能拿到时，填一段 JS，引擎会改用内置 WebView 加载播放页并注入执行，详见WebView JS 解析。注意其生效前提是 pattern 解析出的地址是一个网页而非直链：JSON 源请配合 "pattern": "link"；HTML 源请让 urlSelector 提取播放器页地址（如 iframe@src）。

多步精准提取 steps（可选，优先于 pattern 生效）

播放地址藏在多层页面后时（播放页 → 播放器页 → 直链），可配 steps 数组做纯 HTTP 逐页请求+提取，无 WebView、无 hls.js 竞态：第一步输入为剧集链接，每步请求上一步结果页面并提取下一步地址，最后一步输出即播放地址。配置后优先于 pattern/urlSelector 生效（两种模式通用）。

"videoUrl": {
  "steps": [
    { "pattern": "selector", "urlSelector": "iframe.iframe@src" },   // 第1步：播放页取播放器 iframe 地址
    { "pattern": "selector", "urlSelector": "#video@src",            // 第2步：播放器页取直链
      "postProcess": "script:var r=String(result);return r.indexOf('http')===0?r:('https:'+r);" }
  ]
}
  • 每步 pattern："regex"（urlSelector=正则，取捕获组 1）或 "selector"/缺省（urlSelector=选择器@属性）；
  • 每步可配旧版字符串 postProcess（含 script: 前缀脚本，result 为输入），用于补协议头、解码等；脚本运行在内置 JS 引擎（完整 ES 标准库，可内联实现 Base64/AES 等算法）；
  • 请求指令：某步 script: 脚本 return 一个 {"__request":true,...} JSON 时，下一步不请求提取结果，而是按指令发起 HTTP 请求——链路中含 POST 表单接口（如解析器 api.php）、需带特定请求头的 GET 时用它： 
    "postProcess": "script:var w=decodeURIComponent(result);return JSON.stringify({__request:true,method:'POST',url:'https://parser.example.com/api.php',fallbackUrl:'https://parser2.example.com/api.php',headers:{'content-type':'application/x-www-form-urlencoded','referer':'https://parser.example.com/'},body:'url='+encodeURIComponent(w)});"
    指令键：url（必填）、method（POST/GET，缺省 GET）、body（POST 请求体）、headers（附加请求头）、fallbackUrl（可选备用地址：主地址请求失败时改用它发同样请求，适合解析接口双域名站点）；指令后必须还有提取步骤（不能以指令结尾）；
  • 每步页面获取失败（超时/卡流）会同地址自动重试一次；中间结果与最终结果会自动做非 ASCII 百分号编码；任一步提取失败即整体失败（报"第 N 步提取失败"）。

本地代理 proxy（可选）

直链流无法被原生播放器解复用时（如伪装成 PNG 图片的 TS 分片），可配本地代理代抓还原，仅显式配置的源生效：

"proxy": { "type": "tsStrip", "referer": "https://player.example.com/", "urlPattern": "\\.m3u8" }
  • type 目前仅 "tsStrip"：App 在本机起代理服务，代抓分片（带 referer 请求头，空串/缺省=不带）并剥离伪装头还原 TS；m3u8 播放列表同步改写走代理，#EXT-X-KEY:/#EXT-X-MAP: 行内的 URI 也一并改写——AES-128 加密流的密钥/初始化段防盗链站点（密钥直连 403）配 referer 即可代抓，无 KEY/MAP 行的播放列表行为不变；找不到 TS 同步头的分片（如 AES 密文分片）原样透传，不影响加密流剥壳；
  • urlPattern（可选）：正则，仅当最终播放地址匹配时才走代理（如 "\\.m3u8" 只包装 m3u8、mp4 直链保持直连——同站直链与 m3u8 混出、或 mp4 根本无需剥壳时必配，避免 mp4 被包进 .m3u8 代理路径导致无法播放）；缺省=总是包装；
  • 代理自动给无后缀 URL 补 .m3u8/.ts 后缀（AVPlayer 按扩展名识别格式）；包装失败自动回退原始地址。

字段后处理

任何 itemSelectors 字段、详情封面（coverPostProcess）、HTML 文本/属性选择器都可以挂 postProcess，类型是 ProcessConfig：

"imgUrl": {
  "selector": "img@src",
  "postProcess": {
    "type": "pipeline",                       // 串多步
    "steps": [
      { "type": "string", "stringProcess": { "type": "replace", "search": "/thumb/", "replace": "/" } },
      { "type": "condition", "condition": "result", "trueValue": "有图", "falseValue": "无图" },
      { "type": "transform", "transform": { "map": { "1": "国语", "2": "日语" } } }
    ]
  }
}

六种 type：

type用途关键字段
"string"字符串处理（最常用），具体操作见下表stringProcess
"condition"按条件替换整值condition（表达式，result 代表原值）、trueValue、falseValue
"transform"映射 / 模板transform.map（值→值映射表）或 transform.template（${input} 占位）
"script"受限沙箱脚本script（JS 片段，result=原值，context=自定义上下文，可用 Math 与 utils.string/number/array/condition 工具），return 返回结果
"expression"简单表达式求值expression，如 "result * 2"（仅算术）
"pipeline"串联多个步骤steps: ProcessConfig 数组，依次执行

stringProcess（StringProcessConfig）四种操作：

type关键字段说明
"regex"pattern、flags（默认 g）、group（捕获组号）正则提取，返回指定捕获组（默认第 0 个匹配）
"replace"search（正则）、flags、replace正则替换全部命中
"substring"start、end（数字下标或字符串标记）取子串；填字符串时按"标记之后 / 标记之前"定位
"split"delimiter、index分割后取第 index 段（默认第 0 段）
后处理出错时不会中断解析，而是返回原值，可放心使用。

WebView JS 解析（iframeSelector）

当播放直链必须执行站点 JS 才能获得（加密参数、动态请求、防爬校验等），给 videoUrl 配置 iframeSelector：

"videoUrl": {
  "pattern": "link",                    // 或其他 pattern：先解析出"播放页地址"，再交给 WebView
  "iframeSelector": "(function(){ ... return 直链或 'ERR_错误码'; })()"
}

执行流程：

  1. 引擎先按 pattern 解析出一个播放页地址（pattern: "link" 时直接用选集 url）；
  2. 内置 WebView 加载该页面，注入执行 iframeSelector 这段 JS（立即执行表达式）；
  3. JS 返回值即播放直链，交由播放器播放。

约定：

  • JS 返回 http(s):// 开头的字符串视为成功；返回 ERR_ 前缀的字符串视为失败并提示；
  • JS 返回 PENDING 表示"已安装异步钩子"：直链要等页面运行时才产生（如 hls.js/MSE 播放器、运行时解密），JS 先同步检查一轮，找不到就 hook XMLHttpRequest/fetch、轮询 performance 资源记录、轮询播放器实例（Artplayer.instances[].option.url、video.currentSrc）等，拿到后调用 window.animeBridge.onLink(直链) 异步回传（失败可回传 ERR_ 串），引擎会继续等待至超时；
  • 回传的直链不要求带 .m3u8/.mp4 等扩展名：不少解析站的代理直链是无扩展名地址（形如 https://cdn.xxx.com/8a3f.../video/tos/.../）。只要能确认是播放源（播放器实例的 url、<video> 的 http src），直接回传即可；但 iframe 嵌套的第三方播放器页地址仍需人工甄别，不要当直链回传；
  • JS 中严禁出现 _|_ 子串（它被用作地址与 JS 的内部分隔符）；
  • JS 里可以用 XMLHttpRequest 同步请求站点接口、读取 document / location，等于在站点自己的页面环境里写"半自动解析脚本"。

复杂示例可参考仓库规则列表中使用 WebView JS 解析的现成源：页面加载后从内嵌数据中找剧集 ID，计算校验头，请求解析接口取直链。

除 JS 通道外，引擎还内置网络层 m3u8 嗅探（零配置，自动生效）：解析用 WebView 的所有 https 请求会被旁路监听（不拦截、不影响页面加载），一旦出现 .m3u8 请求，引擎会拉取该地址验证内容（主播放列表直接采用；普通切片流要求总时长达标，过短的疑似贴片广告仅作候补），随后自动交付播放。JS 通道与嗅探通道并行工作，谁先拿到可用地址谁生效。因此对"hls.js 播放、直链只出现在网络请求里"的站点，iframeSelector 只需返回 PENDING 甚至可以省略嗅探逻辑，交给引擎完成。

对带真实点击校验（isTrusted）或风控较强的站点，纯 JS 可能无法稳定通过。应用对此类源有兜底策略：自动尝试失败后会弹出 WebView 让用户手动点击辅助播放，配置无需额外处理。辅助窗口内置通用捕获（页面 .m3u8 请求、Artplayer 播放器实例、<video> http 直链），多数站点用户只需点一下站内播放按钮即可自动完成捕获并关闭窗口。

写源实战教程

以给一个模板站写 HTML 源为例，整体流程约 30-60 分钟：

第 1 步：侦察站点（10 分钟）

  1. 电脑浏览器打开目标站，F12 打开开发者工具；
  2. 搜一个关键词，看搜索结果页 URL 规律（如 /index.php/vod/search/wd/关键字.html）；
  3. 在 Elements 面板用选择器箭头点一个结果卡片，记下它的 class（如 div.module-card-item）；
  4. 同法确认：封面 img 的真实属性（src 还是 data-original）、标题、集数角标、详情链接；
  5. 打开详情页：标题/简介/封面/选集（单路线还是多路线）/推荐的选择器；
  6. 打开播放页：Network 面板找真实视频直链（m3u8/mp4）——看它是直接写在 HTML 里、内嵌 JSON 里，还是接口返回的。这决定 videoUrl.pattern 怎么填。
苹果 CMS（MacCMS）模板站结构高度一致，本仓库的模板站 HTML 源几乎可以直接换 baseUrl 复用，改前先对比一下 class 名。

第 2 步：搭骨架（5 分钟）

两种方式任选：

  • 在电脑上复制一个结构最接近的现有源文件，替换 key/name/baseUrl 等基础信息；
  • 或直接在应用内"添加新数据源"新建（每个输入框的含义见应用内编辑器对照）。

第 3 步：逐块填写（20 分钟）

按 搜索 → 详情 → 选集 → videoUrl → 首页 的顺序填（这是排查问题的自然顺序：先能搜到，再能进详情，再能播放，最后美化首页）。在应用内编辑时每个输入框都有提示文案，随时可切换"源模式"查看 HTML/JSON 两种填法示例。

第 4 步：真机验证（10 分钟）

  1. 应用内编辑：点保存即生效；JSON 文件方式：把文件放到手机或直接用 raw 链接；
  2. JSON 文件方式：AnimeZ → 我的 → 设置 → 视频源 → 更多菜单 → 导入数据源 → 选择覆盖导入；
  3. 依次验证：搜索出结果 → 首页显示 → 点进详情 → 选集完整 → 播放成功 → 推荐显示。
修改配置后必须重新覆盖导入才会生效，这是最常见的"改了没反应"原因。

调试与常见问题

排查顺序

搜索没结果 → 检查 search.videos；有结果但点进去空白 → 检查 detail；详情正常但没选集 → 检查 episodes；选集有了但播不了 → 检查 videoUrl。

常见问题

症状原因与解法
改了配置没反应JSON 文件方式：修改后必须重新"覆盖导入"才会生效；应用内编辑：确认点了"保存"（标题栏保存按钮变色）
列表为空listSelector 没命中任何元素 / JSON 路径写错。用浏览器控制台 document.querySelectorAll('...') 验证选择器
标题正常但没图封面在懒加载属性里，把 img@src 换成 img@data-original 等
点详情跳转错误相对路径没拼 baseUrl：urlNeedBaseUrl 设为 true
图片加载失败站点图片是 http 而 app 强制 https？检查 enabledHttps；或站点有防盗链（Referer 校验），暂无解
播放报"解析失败"正则没匹配上：把 urlSelector 正则放到播放页源码里搜一遍确认；注意 JSON 转义（\" 在 JSON 里要写 \\\\\"）
选集只有一条路线多路线站点用了单路线写法：补 routeTitlesSelector + routeContainersSelector
JSON 源接口 401/403需要登录：配置 login，并在源列表长按源卡片登录；或接口要求特定请求头，补 requestHeaders
WebView JS 解析返回 ERR_JS 内部报错。返回值以 ERR_ 开头会显示在错误提示里，按码回溯 JS 逻辑
